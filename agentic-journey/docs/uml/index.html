Agentic Journey Runtime

The primitives from the journey design doc, built small and run on Docker: one model call path, scope-bound memory, a warm pool of credential-free sandboxes, and a human gate on the one write that matters.

The split everything else hangs from

The reasoning plane holds credentials and the actor's resolved scope. The execution plane holds neither. A code string crosses out, stdout comes back, and every authenticated write happens on the trusted side.

Azure forces this shape — the managed code interpreter cannot make outbound calls — and it is worth keeping locally, because it is what bounds the blast radius of model-authored code to one disposable container.

Primitives, as classes

Each primitive is one module. The relations that matter are the ones that cannot be reversed: scope is derived from identity and never accepted from a caller, the tool registry reaches the sandbox pool while the sandbox reaches nothing, and both memory kinds sit behind one store boundary so either can be swapped for its Cosmos DB equivalent alone.

One turn, from token to answer

Every hook binds to a point the agent framework already exposes, so the interception layer is a set of functions rather than a subsystem. The approval gate is the clearest case: the tool body never runs, the run ends with a deferred request, and the resumed run continues from the same message history.

A verifier subagent — cheap model, own budget, typed verdict — runs inside the output validator. When it rejects an answer past the retry budget, the turn returns status: degraded rather than a plausible answer dressed as a success.

A sandbox is a cache, not a record

No Azure primitive migrates a running sandbox between hosts, so this design refuses to need one. After every step the workspace is tarred to blob storage; a killed container, an expired cooldown and a host fault then all cost the same thing — one rehydration on the next turn.

Not built

  • Vector retrieval and embeddings — nothing here retrieves by similarity yet.
  • Real authentication. A token dictionary stands in for the identity provider.
  • Multi-pool placement. One pool, one host; the 600-session ceiling is an Azure question.
  • Prompt-injection defenses and cost accounting.
  • System methods — still undefined in the source design.
